# 直播覆盤工作台 Stream Review Workbench

每一場直播結束後，貼上逐字稿、填入數據，AI 整理出「本場最大的問題」與「下一場要改善的任務」，
每一條問題**附逐字稿原文出處，並由伺服器逐字核對**——運營看一眼就能判斷 AI 講得對不對。

這是內部營運系統的第一個模組：帳號、角色權限、資料模型與管理介面照正式規格建置，
後續模組直接在同一個底座上長，不重寫。

## 這個工具的三個設計立場

1. **AI 的每一句話都要能被驗證。** 問題必附原文引用；伺服器把引用跟逐字稿逐字核對，
   對不上的在畫面標紅。我們不假裝 AI 不會出錯——我們讓錯誤一眼就被看到。
2. **不硬湊。** 一場表現好的直播，AI 列出來的可能全部是「輕微」等級的教練建議，
   這是正常的。為了湊滿三條而編出來的問題，會讓使用者對整個工具失去信任。
3. **改善任務必須可檢驗。**「加強互動」這種驗不了的不收；
   要的是「每 10 分鐘至少報價一次」這種下一場結束就能打勾的標準。

## 功能（第一階段）

- 登入（PBKDF2 十萬次雜湊＋HttpOnly session cookie；同信箱連續失敗 8 次鎖 15 分鐘）
- 新增直播：直播主、日期、數據（總觀看／在線峰值／留言／詢單）、逐字稿
- AI 覆盤：最多 3 個問題（含嚴重度：重大／中／輕微＋原文引用＋時間位置）
  ＋最多 3 個改善任務（含可檢驗標準）
- 覆盤結果頁：引用核對標示、一鍵複製成 LINE 訊息
- 直播列表

第二階段（運營修改確認、保存追蹤、跨場重複問題、改善達成追蹤）的資料欄位已就緒
（`review_items.status / final_text / operator_note`），屆時只開 UI，不動資料庫。

## 技術

| 層 | 選擇 |
|---|---|
| 執行 | Cloudflare Workers（靜態頁走 assets） |
| 資料庫 | Durable Object（SQLite）。與 D1 同方言，schema 可原封搬遷 |
| AI | Google Gemini（`GEMINI_MODEL` 可設定，預設 gemini-3.7-flash） |
| 前端 | 無框架 HTML/CSS/JS |

## 本機開發

```bash
# .dev.vars（不進 git）：
#   GEMINI_API_KEY=...
#   SETUP_CODE=任意一次性代碼
npx wrangler dev --port 8788
# 開 http://127.0.0.1:8788 → 首次會導去 setup 頁建立管理員
```

測試：

```bash
node scripts/test_prompt.mjs   # Prompt 品質閘門：打真的 Gemini，
                               # A 場（埋 3 個事故）至少抓 2 且評「重大」；
                               # B 場（正常場）不得出現「重大」；引用全部逐字核對
```

## 資料

`data/` 內是**虛構**的中古車直播逐字稿（測試用，非任何真實直播）。
本專案不含任何真實客戶資料；正式部署設定與公司資料不進版本庫。
