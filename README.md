# AI 指揮中心 — LINE 官方帳號客服後台

多人共用的 LINE 官方帳號客服系統：運營把客戶對話指派給訊息手，被指派的人獨占那通對話，
同層級互相看不到，管理職看得到全部。給的是自建、資料在自己手上的版本。

## 為什麼要自建

市面上的第三方客服後台把對話鎖在自己的雲端：拿不到完整匯出，也沒有開放 API，
公司累積幾年的客戶對話等於押在別人那裡。這套的取捨相反 ——
資料庫是自己的，schema 是公開的，要接什麼 AI 都行。

## 三個設計立場

1. **權限在資料庫層擋，不在畫面層。** 每一個查詢都帶權限條件，不是查完再過濾。
   實測用訊息手帳號**直接打 API 繞過畫面**去讀別人的對話 —— 擋得住。
2. **看不到就回 404，不回 403。** 回 403 等於告訴對方「這個對話存在，只是不給你看」，
   那本身就是洩漏。
3. **客戶的主鍵是電話，不是平台 ID。**
   LINE 的 userId 綁在單一官方帳號上（[官方 FAQ](https://developers.line.biz/en/faq/)），
   換帳號就對不回來。所以 `contacts` 以自有身分鍵（電話）為主軸，
   `contact_channels` 才放各渠道的 ID —— 換官方帳號，客戶資料仍然對得回去。

## 功能

- 登入（PBKDF2 十萬次雜湊＋HttpOnly session；同信箱連續失敗 8 次鎖 15 分鐘）
- 三個角色：管理者 admin／運營 operator／訊息手 agent
- **訊息中心**：收件匣（全部／未指派／我的）、對話串、回覆、客戶資料欄
- **指派**：運營指派給訊息手，`assignment_log` 留下誰在什麼時候把誰的對話轉給誰
- **總覽**：進行中對話、未指派、待回覆、客戶分級分布、訊息手戰況、獲客渠道
- 客戶分級 S／A／B／C，獲客渠道分流統計
- 手機版：單欄切換（收件匣 ↔ 對話），375px 實測無橫向捲軸

## 還沒做

- **不接 LINE API**：訊息不會真的收發，回覆只寫進本系統的資料庫
- 標籤、廣播、自動回覆、跨渠道（FB／IG）合併

## 技術

| 層 | 選擇 |
|---|---|
| 執行 | Cloudflare Workers（靜態頁走 assets） |
| 資料庫 | Durable Object（SQLite）。與 D1 同方言，schema 可原封搬遷 |
| 前端 | 無框架 HTML/CSS/JS |

## 本機開發

```bash
# .dev.vars（不進 git）：
#   SETUP_CODE=任意一次性代碼
npx wrangler dev --port 8788
# 開 http://127.0.0.1:8788 → 首次會導去 setup 頁建立管理員
node scripts/seed_inbox.mjs        # 灌入假客戶與對話
```

種子腳本會建立測試帳號（密碼都是 `test-pass-123`）：

| 帳號 | 角色 | 看得到 |
|---|---|---|
| boss@test.local | 管理者 | 全部 |
| operator@test.local | 運營 | 全部，可指派 |
| agent1@test.local | 訊息手 小婷 | 只有指派給她的 |
| agent2@test.local | 訊息手 阿凱 | 只有指派給他的 |

## 資料

種子資料全部是**虛構**的客戶與對話，電話用 `0900-000-0xx` 的假號段。
本專案不含任何真實客戶資料；正式部署設定不進版本庫。
