# 資訊架構（Information Architecture）v0.1

> **9/4 核准（Curry）**，三個調整：① 保留「需要注意」獨立頁；② `/insights/:id` 是各模組共用的鑽取／證據視圖，
> 不是側邊欄主項；③ CEO 總覽維持極簡，但允許小型趨勢圖／sparkline 幫助一眼看方向。

**產品**：訊息到成交 AI 影子控制台。**使用者**：CEO（瑋瑋）、主管、業務。
**一句話原則**：每一頁都要能回答「發生什麼？為什麼？哪裡要注意？證據在哪？下一步做什麼？」

## 全站骨架

```
┌ 側邊欄（常駐）────────┐ ┌ 全域指令列：搜尋客戶／業務／車款，或直接問 AI ──────────────┐
│ ◎ CEO 總覽             │ │                                                              │
│ ▤ 漏斗／價格流失        │ │  頁面內容                                                     │
│ ☰ 需要注意（動作佇列）   │ │                                                              │
│ ▣ 對話／證據            │ │                                                              │
│ ◷ 預約與到店            │ │                                                              │
│ ¥ 成交／營收／毛利       │ │                                                              │
│ ✦ 問 AI                │ │                                                              │
│ ─────────────────────  │ │                                                              │
│ ⚙ 資料與設定            │ │                                                              │
└────────────────────────┘ └──────────────────────────────────────────────────────────────┘
```

- **側邊欄**七個主頁＋一個工具頁。沒有「洞察」「業務」「車款」獨立頁 —— 洞察嵌在各頁頂端，業務與車款是漏斗頁和成交頁的拆解維度。
  多一頁就多一個「這個要去哪裡看」的問題。
- **全域指令列**：打字 → 即時候選（客戶假名、業務、車款、預約、成交）；按 Enter 沒命中實體 → 當自然語言問句送到「問 AI」。
- **角色**：CEO／主管看全公司；業務登入後同一套頁面只剩自己的 lead（SQL 層擋，404 不 403），側邊欄少「成交／營收」。

## 證據鏈（全站共用的漸進揭露）

```
摘要（頁首 AI 一句話）
  ↓ 點卡片
指標／洞察（數字＋claim＋confidence＋n）
  ↓ 「查看證據」
受影響的 lead 清單（客戶假名、業務、車款、階段、結果、最後一則）
  ↓ 點一列
客戶（旅程時間軸：事件依序、每個事件的信心）
  ↓ 事件
實際對話（相關訊息高亮＋「為什麼這則支持結論」）
```
URL 對應：`/overview` → `/insights/:id` → `/conversations/:leadId#event-:eventId`。最多三次點擊到對話。
每一層都保留上一層的篩選（期間、業務、車款），不會點下去就失去脈絡。

## 設計系統的硬規則（70% 主管指揮中心／20% 戰術營運／10% 極簡）
- 底 `#0B0E13` 石墨黑、層 `#10182A` 深藍、面 `#141A24`、線 `#223042`（1px）
- 字 `#E8ECF1`／次要 `#9AA6B4`；數字一律 tabular-nums
- **青 `#4FD1E5`＝可互動與系統狀態；琥珀 `#E9A445`＝偏離常態；紅 `#E5484D`＝只給 critical。** 其他一律灰階。
- 發光只出現在「目前選中」的一個元素上；卡片沒有大留白；圖表只畫有意義的（沒有裝飾用的圓環）

## 1. CEO 總覽 `/overview`

**主要目標**：30 秒內知道「現在什麼需要我」。
**要回答**：今天最重要的一件事是什麼？跟上週比變了什麼？哪裡壞、哪裡好、哪裡怪？
**層級**（由上而下、由重到輕）
1. AI 指揮簡報（四行：發生了什麼／變了什麼／最該注意／今天做什麼；每句可點到 #洞察）
2. 洞察卡列（依嚴重度：critical→low；每張＝標題、claim 標籤、confidence、n、「查看證據」）
3. 漏斗快照（一列：新進線→報價→預約→到店→成交，數字＋轉換％＋週對週箭頭）
4. 四格：營收／毛利／預約／到店（本期 vs 前期）
5. 需要注意（前 5 筆，連到動作佇列頁）
**元件**：簡報面板、洞察卡、橫向漏斗條、KPI 小格、注意清單列。
**動作**：點洞察→證據頁；點簡報句→對應洞察；「重新分析」（管理職）；駁回洞察。
**不放**：任何表格、任何超過 5 筆的清單、業務個人排行（那是主管頁的事）、圖表細節。
**連到**：`/insights/:id`、`/funnel`、`/attention`、`/deals`、`/appointments`。

## 2. 漏斗／價格流失 `/funnel`

**主要目標**：找出漏斗最弱的一段，尤其是報價之後客人去哪了。
**要回答**：每段轉換多少、跟上週比？價格後流失幾位、哪種車型／哪位業務特別嚴重？有多少證據？
**層級**
1. 這頁的 AI 一句話（例：「報價→預約是最弱的一段，43%，前期 61%」）
2. 完整漏斗：新進線→車款興趣→有來有往→報價→預約→到店→議價→成交／流失；每段計數、轉換％、週對週、流失％（最大瓶頸琥珀標記）
3. **價格後流失專區**：本期 N/報價數＝％（前期）；信心分布（確定／強烈建議／可能）；拆解表 ×3（車型、車款、業務）每列可點
4. 階段分布（目前 lead 卡在哪一階）
**元件**：漏斗（水平分段條，不用漏斗形狀裝飾）、拆解表（緊湊、tabular）、期間切換（7／14／30 天）。
**動作**：點任一段或任一列 → 受影響 lead 清單（帶篩選）→ 對話；切換期間；匯出 CSV（管理職）。
**不放**：營收金額（去成交頁）、預約細節、對話內容本身。
**連到**：`/conversations?stage=…&vehicle=…`、`/insights/:id`、`/deals`。

## 3. 需要注意（動作佇列）`/attention`

**為什麼要這一頁**：研究裡最實際的數字是「84% 的 lead 30 天後沒人碰」。「沒人跟進」本身就是最大的一類洞察，而且是唯一
每天都要有人「處理掉」的頁面 —— CEO 總覽只放前 5 筆，主管要的是全部、可分派、可結案。
**主要目標**：把今天該回的客人清完。
**要回答**：誰在等、等多久、為什麼進這個清單、該誰做、做了沒。
**層級**
1. 四類計數：急迫未跟進／報價後未跟進／預約已過未到店／貸款未回
2. 佇列表（依優先級）：客戶假名、業務、車款、原因、等了多久、優先級、狀態
3. 建議動作（來自洞察的 actions）：核准／駁回／完成＋結果備註（**閉環：「上次的動作有沒有用」寫在這裡**）
**元件**：分類籤、緊湊表、動作卡（含 owner_role）。
**動作**：點列→對話；標「已處理」；核准／駁回建議；篩選業務。
**不放**：漏斗、營收、任何圖表。
**連到**：`/conversations/:leadId`、`/insights/:id`。

## 4. 對話／證據瀏覽器 `/conversations`、`/conversations/:leadId`、`/insights/:id`

**主要目標**：看到 AI 結論背後的原文。這是信任的來源。
**要回答**：這位客人經歷了什麼？系統偵測到哪些事件、多有把握？哪幾則訊息是證據？下一步建議？
**層級（三欄）**
- 左：可搜尋的清單（篩選：階段、業務、車款、結果、期間、只看有洞察的）
- 中：對話時間軸；**偵測到的事件插在訊息之間**（例：「── 報價 ── 確定」「── 價格後流失 ── 強烈建議」）；證據訊息高亮＋註解
- 右：客戶卡（假名、分級、首次進線、車款、業務、階段、結果）→ AI 摘要（事實）→ 異議／意圖（假設，標明）→ 建議下一步 → 這個 lead 出現在哪幾條洞察
**證據頁 `/insights/:id`**：洞察標題＋metric＋claim＋confidence → 受影響 lead 表 → 點列展開該 lead 的證據訊息（前後各 2 則脈絡）。
**動作**：搜尋；篩選；標記「已看」；駁回某則證據（回饋給規則）；跳到 Super 8 原對話（外連，之後）。
**不放**：全公司數字、圖表。
**連到**：所有頁都連進來；出去到 `/attention`。

## 5. 預約與到店 `/appointments`

**主要目標**：預約有沒有變成到店、到店有沒有變成成交；今天哪幾個要盯。
**要回答**：提議→成立→到店→成交各多少？爽約率？今天／明天的預約？最近到店的結果？
**層級**
1. 一列數字：提議／成立／改期／取消／爽約／到店；預約→到店％、到店→成交％（週對週）
2. **時間軸**：今天與未來 7 天的預約（時間、客戶假名、業務、車款、狀態）；已過期未到店琥珀
3. 需要盯的預約（已過未到店、明天沒確認）
4. 最近到店結果（買／議價中／離開）＋原因摘要
**元件**：狀態計數列、垂直時間軸（戰術風）、緊湊表。
**動作**：點→對話；標記狀態（v0.1 手動：到店／爽約）；篩選業務。
**不放**：漏斗其他段、營收。
**連到**：`/conversations/:leadId`、`/funnel`（預約→到店那段）。

## 6. 成交／營收／毛利 `/deals`

**主要目標**：這段時間賺了多少、每台留多少、誰／哪款車撐起來的、哪裡在漏錢。
**要回答**：成交／流失幾台？營收、毛利、平均毛利、毛利率？趨勢？依業務／車款？哪台賠錢？流失原因分布？
**層級**
1. 一列數字：成交、流失、營收、毛利、平均毛利、毛利率（本期 vs 前期）
2. 趨勢圖：每週營收與毛利（10 週）
3. 兩張表：依業務（成交、營收、毛利、平均成交天數）、依車款（詢問、成交、詢問→成交％、毛利）— 高詢問低轉換琥珀標記
4. 成交明細表：日期、客戶假名、業務、車款、售價、毛利、天數（低於成本紅）
5. 流失原因分布
**元件**：財務 KPI 格、折線圖、tabular 表。
**動作**：點明細→對話；切換期間；匯出（管理職）。
**不放**：漏斗上游、預約細節、AI 敘事（這頁是帳）。
**連到**：`/conversations/:leadId`、`/funnel`（車款拆解）。

## 7. 問 AI `/ask`

**主要目標**：老闆用自己的話問，得到有證據的答案。這是最 JARVIS 的一頁，也最容易變成空談，所以規矩最嚴。
**要回答**：「這週為什麼成交變少？」「報價後消失的客人有誰？」「哪台車問很多賣不掉？」「哪些預約要盯？」
**層級**
1. 大輸入框＋四個範例問句
2. 答案：一段結論（事實／假設分開標）→ 引用的數字（可點到來源頁）→ 受影響 lead（可點）→ 一張支持圖（只在有意義時）→ 建議動作
3. 「我怎麼算的」摺疊區：用了哪些期間、哪些事件、樣本數
**元件**：指令輸入、答案卡、引用 chip、小圖。
**動作**：問；點引用→對話／頁面；把答案存成洞察（管理職）。
**不放**：側邊欄以外的任何導覽、多輪聊天歷史牆（保留最近 5 問）。
**連到**：全站。

## 8. 資料與設定 `/data`（工具頁）

匯入 bundle、重算漏斗、重跑洞察、SLA 與門檻、成員、來源狀態（模擬／真切片／瑋瑋的表：筆數、最後更新）。只有 admin。

```
overview ──點洞察──▶ insights/:id ──點 lead──▶ conversations/:leadId
   │                                                    ▲
   ├──漏斗快照──▶ funnel ──點段/列──▶ conversations?filter ┤
   ├──需要注意──▶ attention ──點列──────────────────────────┤
   ├──四格──────▶ deals / appointments ──點列───────────────┘
   └──指令列──▶ ask ──引用──▶ 任一頁
```

## 10/26 展示走的路線
overview（30 秒）→ 點「價格後流失」洞察 → 證據頁看到 3 位客人 → 點一位看到原文 → 回 attention 核准一個動作 → ask「這週為什麼成交變少」。
六個畫面裡先做這條線上的五頁到可展示；成交頁用真切片的數字。
