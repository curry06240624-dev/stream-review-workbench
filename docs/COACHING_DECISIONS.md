延伸 `docs/STAFF_EFFECTIVENESS.md`。目的不是排名，是回答：表現好的人為什麼好、做了什麼不一樣、哪些行為看起來有關、表現弱的人能改什麼、老闆該做什麼決定。

## 1. 訊息層行為特徵（`src/engine/behavior.ts`）

每個 lead 一列 `behaviors.features`（JSON），只在「情境出現過」時才有鍵，員工之間比的才是同一種情境：

| 鍵 | 情境 | 定義 |
|---|---|---|
| first_response_min | 每個客戶 | 客戶第一則 → 業務第一則（分鐘） |
| median_response_min | 有客戶訊息 | 客戶每則 → 業務下一則的中位數 |
| followup_24h_rate | 客戶沉默 ≥24h | 業務講完一輪、客戶 24h 沒回的次數中，7 天內有再跟進的比例 |
| asked_after_price | 有報價 | 報價後、下一則客戶訊息前，業務有沒有接一個問題（看車邀約不算） |
| objection_clarified | 客戶說太貴 | 異議後 24h 內第一則業務訊息是問題或提方案（不是「已經是底價」） |
| proposed_after_intent | 客戶表達急迫 | 48h 內有具體看車邀約（要有時間或「約」的字眼），或 72h 內預約成立 |
| fin_answered | 客戶問貸款 | 回覆給了數字（頭期／月付／利率／試算）或轉專員；「問一下專員」不算 |
| postvisit_24h | 到店沒當場買 | 到店後第一則業務訊息在 24h 內 |
| budget_clarified / opening_question | 每個客戶 | 報價前就問預算；第一句就是問題 |
| reactivated_by_staff | 客戶沉默 ≥7 天 | 回流前 7 天內有這位業務的跟進，且回來之後有往下走 |
| escalated | 每個客戶 | 主管或同事介入過 |
| discount_pct / gp_margin | 成交 | 折讓佔定價、毛利率（守住毛利） |

評測（`scripts/eval_loss.mjs` 第三段）：每個特徵對模擬器真值命中率 ≥ 0.9，目前全過。

## 2. 對照怎麼算（`src/engine/staff.ts`）

- 表現最佳組＝成交率達門檻（已結案 ≥10）者依 Wilson 下界排前 3–5 位；需關注組＝樣本夠、且至少一項明確落後團隊（成交率／報價後續走／預約轉換低 10 點以上、首次回覆是團隊 2 倍以上且 ≥30 分鐘、沉默後跟進低 20 點以上）的 1–3 位。
- 對照表每列：表現最佳組池化值、需關注組池化值、團隊、兩邊 n；只有 n≥5 且差距夠大（比例 15 點、分鐘 1.8 倍）才列為「觀察到的關聯」。
- 行為 × 結果關聯（全團隊、以 lead 計）：有做到 vs 沒做到的客戶成交率，各附 n。這是關聯，畫面與 AI 都不准寫成因果。
- 同儕分層：客戶中位車價偏離團隊 35% 以上的人加註 `peer_note`（同價位帶同儕與同帶成交率）。

實測（模擬四個月、588 位客戶、最近 30 天）：表現最佳組首次回覆 15 分鐘 vs 需關注組 536 分鐘、報價後接問題 77% vs 19%、開場問預算 59% vs 17%；成交率 70% vs 39%。

## 3. 教練迴圈（`src/engine/coaching.ts`）

**個人教練計畫** `buildCoachingPlan`：主要問題（漏斗層）→ 跟較強同儕相比（行為層，表現最佳組；本人若在最佳組則比其他同事）→ 建議（每條：改什麼、為什麼、證據、像哪個成功模式、信心）→ 證據（受影響客戶數、流程面優先的流失對話、團隊基準）→ 訊息改寫範例（從本人真實訊息挑：報價只丟數字、貸款沒答、異議直接收尾、到店後太晚跟進；改寫版是模板，`POST /api/coaching/:id` 會請 Gemini 潤稿，數字白名單照舊）→ 強項 → 資料不足的項目。
**永遠不代發**：範例只是教練建議，畫面標「教練建議，不會自動發送」。

**閉環**：決策卡「建立教練行動」→ `POST /api/mgmt-actions` 存基準快照（該指標、k/n、期間）→ 之後 `GET /api/mgmt-actions/:id` 算建立後到現在的同一指標 → 前後對照（至少 7 天、樣本達門檻才下結論；標記「同一期間其他改變也會影響」）。`status=done` 時把「後」快照寫進 `actions.after`。

## 4. 成功模式庫

10 個模式（快速首次回覆、報價後接問題、異議後先釐清、高意圖立刻約看車、貸款講得具體、到店後 24h 跟進、把沉默客戶叫回來、到店後成交強、守住毛利、找主管或同事協助）：示範者（達門檻的人）、樣本、關聯的成交率、代表證據（示範者成交案裡的那則訊息）、信心（n≥20 強烈建議、≥8 可能、否則樣本不足）。

## 5. CEO 決策卡與行動中心

`computeDecisions` 八條規則：報價後續走低於團隊的人 → 教練；團隊沉默後跟進 <60% → 流程；流失原因較前期上升（≥3 且 ≥1.5 倍）→ 檢視貸款／報價／流程；高量低毛利 → 檢視折讓；急迫客戶 24h 沒人回 → 今天分回去；值得教全隊的模式（關聯 ≥15 點、n≥15、≥2 位示範者）→ 寫成教材；交接後成交率 <40% → 檢視交接；表揚第一名。每張卡：為什麼重要（影響人數）、觀察到的差異（對照數字）、建議行動、預期衡量、指標鍵、連結。
行動列：issue／對象／負責人／優先／期限／狀態／結果／前→後。

## 6. API

| 路由 | 用途 |
|---|---|
| `POST /api/admin/analyze` | 角色 → 行為特徵 → 流失原因（DO 本地跑） |
| `GET /api/staff?days` | 總表：指標、排名（9 維度）、表現最佳、需要關注、對照、關聯、模式庫、矩陣、組合 |
| `GET /api/staff/:id?days&refresh` | 個人檔案：指標、名次、教練計畫、本期客戶、角色、組合 |
| `POST /api/coaching/:id` | 重算教練計畫（可 AI 潤稿） |
| `GET /api/loss?days&reason` | 流失原因彙總：本期 vs 前期、分項（業務／車款／車型／階段／價格帶／組別）、清單、推定流失 |
| `GET /api/loss/lead/:id` | 單一客戶的流失分析與證據 |
| `GET /api/decisions?days` | 決策卡 |
| `GET/POST /api/mgmt-actions`, `GET/PATCH /api/mgmt-actions/:id` | 管理行動中心（基準快照、前後對照） |
