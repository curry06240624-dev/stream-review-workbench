# 真實資料流（2026-09-05 依瑋瑋公司訊息組運營「黎」與直播部運營「綠化」的說明）

這份文件記的是**公司實際怎麼運作**，以及系統為了對上它改了什麼。規則改了要同步改這裡；配對準確率用 `scripts/eval_reconcile.mjs` 量。

## 0. 期間怎麼算（2026-09-08）

- 所有「最近 N 天」預設**以資料最後一天為準**（`MAX(conversations.last_message_at)`＋1 秒；畫面標「資料截至 9/6 16:20」），側欄可切「到今天」；漏斗的沉默判定（不活躍 7 天、推定流失 21 天、報價後 72 小時）也用同一個基準，所以資料沒更新時數字不會隨日曆漂移。
- **新進線＝第一則非選單客戶訊息**（`leads.first_real_at`；打字、照片、貼圖都算）。只加好友／只點圖文選單的人是 lead（SABC C）但不算進線，畫面另列「只加好友／點選單 N 位」。按鈕文字清單在 `src/model/menu.ts`。

## 1. 客戶怎麼進來、誰在回

```
直播／影片 → 客人手動加官方 LINE → 訊息組在 Super 8 回覆（不是業務）
        → 客人到店 → 接待群貼文「客戶名／車款／到店時間／誰指派」→ 這時才指派業務
        → 業務接待、議價 → 成交群貼文「送貨囉」→ 過戶／交車
```

- **訊息組**（`users.job='chat'`）回線上訊息；**業務**（`job='sales'` 或 `'both'`）到店接待、成交。
  訊息面指標（首次回覆、報價後續走、沉默後跟進、行為特徵）算在線上回訊息的人；成交面指標（到店→成交、成交率、毛利）算在接待群指派的業務。
  兩者都做的人（`both`）兩組幾乎一樣。歸因角色多一種 `chat_handler`；訊息組→業務的移交**不算交接**。
- Super 8 的座位有人是借來／共用的（`users.seat_shared=1`）：那個人的訊息面指標不可信，畫面標「共用帳號」，只算到團隊。
- 員工在各系統名字不一樣（LINE 群暱稱、Super 8 帳號、車源表寫法）：全部進 `staff_aliases`，貼文的發文人、接待群「誰指派」、貼文裡的「業務」欄都經過它對回同一個人。對不到的在畫面標「暱稱表要補」。

## 2. 訊息在哪裡、哪些看不到

| 來源 | 有的 | 沒有的 |
|---|---|---|
| Super 8（API／MCP，瑋瑋處理） | 客人訊息、訊息組在 Super 8 回的 | 訊息組在 **LINE 官方後台打的字**、LINE 通話、業務自己拉的貸款群 |
| LINE 官方後台匯出 | 客人訊息、官方後台回的 | Super 8 回的 |
| 內部群組（LINE 匯出 .txt） | 入庫／接待／成交／估車群的貼文 | 只有入庫群有機器人；其他群靠匯出 |

所以每一段對話都有 **涵蓋程度**（`conversations.coverage`）：`full`／`partial`／`low`。匯入時沒給就用規則推：客人提到「電話裡講的」、引用紀錄裡沒有的回覆、只有客戶訊息超過兩天 → 不是 full。
**不是 full 的對話不算回覆速度、不算沉默後跟進、流失原因不判「回覆太慢」「跟進不足」**（看不到的回覆不能當成沒回）。畫面在對話標題與右欄標「涵蓋不完整」。

## 3. 三種貼文的格式與解析（`src/engine/posts.ts`）

**成交群「送貨囉」**（火箭 9/4）：年份／車型／顏色／車號／訂金（現金or匯款）／售價／同行/庫存／送貨單位／備註。
- 沒有客戶、沒有業務（缺欄列在 `missing`，畫面標琥珀）；車號常空白；同行車寫車行名（誠鑫）；送貨單位會寫「應該阿富」（`delivery_uncertain`）；貸款結果在備註（過件／倒件）。
- 新格式建議加兩欄 `客戶：`／`業務：`，解析器已經認得。
**估車群**（梨子 9/5）：車型／年份／版本／顏色／里程（萬）／權威／天書（萬元）／車換車or純賣／客人理想價格。行照照片永遠不入庫（`scrubMessage`）。
**接待群**：客戶名／車款／到店時間／誰指派；也認一行式「陳先生 Altis 14:30 阿凱」。到店時間用貼文時間（台灣時區）當基準解析「下午3點」「明天 15:00」。
**LINE 匯出檔**：`2026.09.05 星期六` 日期行 ＋ `HH:MM<tab>發文人<tab>內容`，多行合併，系統訊息（收回、加入群組、通話）略過。同一則靠 `hashId(時間|發文人|內容)` 去重。

貼進來的地方：畫面「待確認配對」底下的貼上框，或 `POST /api/admin/import-group {kind: auto|deal|reception|appraisal, text}`。每一則先落 `group_posts`（稽核），解析成功才連到 `deal_reports`／`visits`／`appraisals`。

## 4. 配對（`src/engine/reconcile.ts`）

| 對象 | 確定 | 強烈建議 | 可能 |
|---|---|---|---|
| 車 | 車牌相同 | 年份＋車型＋顏色在車源表只對到一台；或用客戶正在談的那台 | 對到多台（列候選） |
| 客戶 | 貼文寫了客戶名；或同一台車帳本同一天已有成交 | 同一台車近期有到店／議價、或 45 天內有往來的客戶只有一位（同分時成交時間最接近貼文的勝出） | 接待群 ±14 天看同車款的客戶 |
| 業務 | lead 指派的業務 → 接待群指派 → 貼文寫的業務 | | 發文人本身是業務 |

- 有售價、車與客戶都有、其中一個「確定」另一個至少「強烈建議」→ **自動配對**（老闆可撤銷）；同行車只要客戶名確定也自動；有候選 → **待確認**；都沒有 → **無法配對**。
- **同行的車不用年份車型去猜**（不在車源表，猜到的是庫存車，成本會算錯），只認車牌。
- 每一步的理由寫進 `match_reasons`，畫面照抄。候選（`candidates`）給下拉選單，也可以搜客戶名指定。
- 確認後：連到既有的成交（帳本已有）或新建一筆；lead 變成交、對話關閉、車標已售；重算該 lead 的漏斗與角色。撤銷／拒絕全部還原（`candidates.applied` 存還原用的快照）。

準確率（模擬資料 235 則）：期望自動的 95% 自動且正確、錯配 0、期望待確認的 100% 沒有錯配。門檻：錯配 ≤1%、該自動的 ≥90%。

## 5. 毛利怎麼算、怎麼標

- 正式毛利只有會計有（員工無權限）。系統的毛利＝**售價－車源表成本**，一律標「估算」（`deals.gp_is_estimate=1, cost_source='sheet'`）。
- 同行的車、車號空白對不到車 → **沒有成本**（`cost_source='none'`）：這筆不算進毛利、毛利率、每台毛利、低於成本；所有頁面標「無成本」，並顯示「n 筆無成本未計」。
- 決策中心多兩張卡：「n 筆成交沒有成本，毛利算不出來」、「n 則送貨囉貼文還沒對到客戶或車」。
- 之後會計給月成交成本表 → 匯入時 `cost_source='accounting'`，畫面不再標估算（待做）。

## 6. 到店

有接待群紀錄（`visits.source='reception'`）時，它是到店的權威來源；對話裡推測的到店一律降為「不確定」，不進轉換率（`funnel.ts` 的 `hasReception`）。接待群「誰指派」同時寫進 `leads.staff_id` 與 `assignment_log`（lead 原本沒業務時）。

## 7. 還要跟公司要的東西

1. 送貨囉貼文加「客戶」「業務」兩欄、車號必填、同行車加成本。
2. 車源表唯讀分享（Google Sheets API v4＋服務帳號，綠化說機器人就是這樣讀的）；狀態用欄位不要用列顏色；「調作價」＝實賣價（談完真正賣的價格），在庫車的估算毛利用它不用開價。
3. 成交群、接待群、估車群最近 60 天的 LINE 匯出檔（Track B 真資料切片）。
4. 會計的月成交成本表。
5. 訊息組每人的 Super 8 座位是否共用；各人在 LINE 群的暱稱。

## 車源表 → 成交／收訂中（2026-09-06，Curry：「用車源表算營收」）

成交群的送貨囉貼文常晚到、車號又常空白，所以帳上的成交先以**車源表**為準（`src/engine/sheetdeals.ts`）：

| 車源表 | 系統 | 售價 | 成本／毛利 |
|---|---|---|---|
| 備註「售出…」或狀態 已售／交車 | `deals.status='sold'`（來源 車源表） | 調作價；沒填就用開價（標 `price_source='sheet_list'`） | 車源表成本 → 估算毛利；沒成本＝無成本 |
| 收訂(軒)／送貸(軒)／過件(安) | `deals.status='sold'`＋`delivered=0`＝**成交・未交車**（Curry 9/6：收訂就算成交；送貸→貸款 pending、過件→approved） | 同上 | 同上 |

- 業務＝狀態括號裡的暱稱：先查暱稱表，再用「名字結尾唯一符合」（安 → 賴安）；對不到就留空並在匯入結果警告（軒 目前對不到，要在資料與設定頁加暱稱）。
- 沒有客戶（`contact_id` 為空，成交明細顯示「車源表，還沒對到客戶」）；送貨囉貼文對到同一台車時 `applyReport` 會把車源表那筆換成貼文的成交（撤銷會放回）。
- 車源表沒有成交日：`closed_at`＝同步當下，但 **`closed_at_source`** 記日期是怎麼來的（2026-09-07 瑋瑋回饋「本週成交 11 台」不對之後加的）：`import`＝第一次匯入就是售出／收訂，日期不明 → **不算本期成交**，總覽／成交頁另列「車源表目前售出／收訂 N 台（日期不明）」；`sheet_diff`＝跟上一份快照比才變的（含從表上消失推定交車）→ 日期≈上傳日，算本期；空＝送貨囉貼文／帳本的真成交日。要有真正的成交日，請訊息組在車源表加一欄「收訂日期」或等成交群匯出。
- 同一台車已有貼文／對話來的成交 → 車源表不再產生（不重複計算）。收訂後車又變回在庫 → 收訂中那筆刪掉。
- 什麼時候跑：匯入 bundle、上傳車源表 CSV（資料上傳箱）都會自動跑；也可 `POST /api/admin/sheet-deals/sync` 重跑。
- **賣掉的車會被從車源表刪掉**（Curry 9/6 確認）：上傳新的一份時跟上一份（上傳箱留著每一份）比對，消失的車 → `stock_status='sold'`、`status_text='車源表已移除（推定已交車）'` → 成交（已交車，成交日＝這次匯入日）。車又回到表上 → 那筆撤銷。所以**每次車源表有變動就再上傳一次**，賣掉的車才記得到。
- 未交車也算營收（收訂即成交）；成交頁有「未交車 N 台」與分頁，AI 事實包帶「成交裡 N 台還沒交車」；備註改「售出」那次匯入，成交日改成那天。
- deals.contact_id 改成可為空（migrate 重建過一次 deals 表，可重入）。
