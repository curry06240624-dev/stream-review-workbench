# AI 分析

## 分工（鐵則）
- **算術全部是程式**：轉換率、計數、營收、毛利、期間對比、漏斗數字 → `src/engine/analytics.ts`
- **洞察是規則推出來的**：門檻＋樣本數 → `src/engine/insights.ts`，每條帶 claim/severity/confidence/metric/evidence
- **AI 只做三件事**：解釋（why，標成「假設」）、建議（actions，註明誰做）、CEO 簡報敘事 → `src/engine/ai.ts`
- 模型：Gemini `gemini-3.7-flash`（既有金鑰），藏在 `gemini()` 一個函式後面可換

## 三道防唬爛閘門（`src/engine/ai.ts`）
1. **事實包白名單**：AI 只拿到我們給的數字（期間、進線、報價、流失率、轉換、預約、到店、成交、毛利、需要注意、已成立洞察）。
   回來的文字裡出現事實包沒有的數字（1–2 位小數字除外，例如「3 位」）→ 那句退回模板。
2. **洞察 id 白名單**：引用不存在的 #id → 丟掉。
3. **假設要標明**：AI 的「為什麼」存成 `summary` 尾端的「假設：…」，畫面跟事實分開；簡報的 why 題目固定要求「標明是推測」。

## 沒有 AI 也要能跑
`GEMINI_API_KEY` 不存在、或呼叫失敗 → `templateBrief()` 直接從數字組句子；洞察的 summary 本來就是規則寫的。
展示現場不能靠一次 API 呼叫成功。

## 9/4 實跑（模擬資料，14 天視窗）
5 條洞察 → AI 補了 5 條假設與 10 個動作，全部通過閘門；簡報八題全由 AI 產出、數字全在事實包內、引用 #1–#5。
整個迴圈 17 秒（兩次 Gemini 呼叫）→ **簡報要預先產（排程），不能在開頁時才算**。
